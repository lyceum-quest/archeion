# Archeion

## ἀρχεῖον

This repo stores all data assets used by [lyceum.quest](https://lyceum.quest) projects: a digital library, readers, and tool sets for Ancient Greek.

Much of it is indeed a mere synchronization of work standing on the shoulders of these giants:
- [Perseus Digital Library](https://www.perseus.tufts.edu/hopper/) ([canonical-greekLit](https://github.com/PerseusDL/canonical-greekLit))
- [First1KGreek](https://github.com/OpenGreekAndLatin/First1KGreek)
- [Opera Graeca Adnotata (OGA)](https://github.com/OperaGraecaAdnotata/OGA)
- [The Diorisis Ancient Greek Corpus](https://figshare.com/articles/dataset/The_Diorisis_Ancient_Greek_Corpus/6187256)

There is also a rapidly growing amount of original "Lyceum Edition" work, most of which is generated by LLMs and thus in want of human review.

The assets are organized as follows:

## Release assets

Runtime database files are distributed through GitHub Releases rather than checked into this repository:

- `texts.db` — reader text library and alignments
- `editions.db` — curated Lyceum Editions and source tracking
- `morph.db` — Greek morphology lookup data
- `lsj.db` — LSJ dictionary data

Releases made by `publish-archeion` carry all four databases, compressed with zstd (`zstd -d texts.db.zst`), with `SHA256SUMS.txt` and a `manifest.json` listing each database's checksum before compression. Download current artifacts from the [latest release](https://github.com/lyceum-quest/archeion/releases/latest). See [`db/`](db/) for schema notes, inventories, and regeneration policy.

Two smaller kinds of release carry what the apps preload: `preload-vYYYY.MM.DD` (`aristos-preload.tar.zst`: every generated work with its passages and lemma index, for Lyceum Study) and `conllu-viz-vYYYY.MM.DD` (the CoNLL-U visualizer's treebanks).

## How data gets here

Archeion holds the whole pipeline, from pinned source corpora to releases; see [`PIPELINE.md`](PIPELINE.md). Generated works live in [`conllu/generated/`](conllu/generated/) (`kai run generate`). The works Lyceum shows are the ones with an import config in [`scripts/lyceum-imports/`](scripts/lyceum-imports/). From there, releases go to staging first:

- **`kai workflow release-staging`** brings Lyceum's databases up to date with Archeion (`kai run sync-lyceum`, which imports only the works that changed), deploys them to Lyceum staging, packs the preload for **Lyceum Study** (the study app at study.lyceum.quest) and deploys it to Lyceum Study staging, and drafts the changelogs. Nothing is published.
- **`kai workflow release-production`** promotes exactly that: it dates the changelogs, deploys Lyceum's databases to production and publishes them as a `vYYYY.MM.DD` release (copying each imported work into [`conllu/lyceum/`](conllu/lyceum/)), then publishes the preload Lyceum Study pins and deploys Lyceum Study.

Learner data (`users.db`) is never published.

## Usage

The release tooling reads its settings from the environment or from a git-ignored `.env` in this repository (see [`.env.example`](.env.example)): `LYCEUM_WEBSITE_DIR` (the Lyceum website checkout, whose `data/` holds the reader databases), `LYCEUM_STUDY_DIR` (the Lyceum Study checkout), and the staging and production hosts. Tasks run with [kai](https://github.com/thebrandonlucas/kai): `kai run <task>` or `kai workflow <workflow>`, as listed in [`Kaifile.roc`](Kaifile.roc).

Then consult the relevant subproject README for file layout, provenance, and maintenance rules.

## Versioning

Releases use Calendar Versioning:

```text
vYYYY.MM.DD
```

A second release on the same day takes a counter, set with `ARCHEION_VERSION` (`vYYYY.MM.DD.2`), and a staging rehearsal of a release is tagged `vYYYY.MM.DD-staging`. Each release tags the commit holding its CoNLL-U snapshot and manifest. Preload releases are tagged `preload-vYYYY.MM.DD` and `conllu-viz-vYYYY.MM.DD`, and `release-YYYY.MM.DD` marks each production release in [`CHANGELOG.md`](CHANGELOG.md).
